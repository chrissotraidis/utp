# UT99 network compatibility

## Current state

The native host now exposes a compact dark direct-connect sheet in the three-dot menu. It reports current path availability, accepts a bare hostname or `unreal://host:port` URL, rejects non-Unreal schemes, remembers the last valid address, and passes the normalized URL to the original v469e engine entry. When an engine session is already active, it routes the player to Unreal Tournament's original Multiplayer menu rather than attempting a duplicate start.

The current-source iPad flow was exercised end to end with a public unmodified endpoint: invalid `https://` input was rejected, `ut99.weba.ru:7777` was normalized, DNS resolved, the server returned `CHALLENGE VER=469`, download managers and `WELCOME LEVEL=DM-CMetal`, and the original engine loaded the remote map. Evidence and exact remaining G8 limits are in `docs/evidence/network/2026-08-24-native-direct-connect-ui/RESULT.md`.

The first live test reached an unmodified public endpoint at `217.154.81.36:7777` (listed as Classic UT99 / `DM-Deck16][`), completed the original browse/login path, loaded the server's current `DM-Phobos` map, possessed the player, and rendered the network HUD. A FIRE interaction reached the live scoreboard/death state. A later session also captured server weapon/death feedback and the in-game `You are dead. Hit [Fire] to respawn` prompt with the GoldenPad controls visible. This is a meaningful partial interoperability pass, not the final multiplayer gate: movement, explicit respawn completion, chat, and map transition still need evidence.

Evidence is in `docs/evidence/engine-startup/2026-08-23-ios-sim-stub/network-deck16-engine.stdout`, `network-deck16-summary.txt`, and `ut99-network-deck16-dead.png`.

After the Apple graphics profile and command-line direct-connect path were rebuilt, the stock endpoint was retested successfully: `DM-Barricade` loaded, the player was possessed, and the live HUD rendered at rank 1/6. Fresh evidence is in `network-stock-profile-engine.stdout` and `ut99-network-stock-profile.png`. The input/death session is in `network-input-session-engine.stdout`, `network-input-session-summary.txt`, and `ut99-network-input-session.png`.

A prior test against `ut99.weba.ru:7777` selected custom `DM-Unreality][` content that reached Metal as `MTLPixelFormatBC1_RGBA` (numeric format 130) and aborted in the simulator. The new Metal-shim fallback now redirects BC1 texture creation to RGBA8 and expands upload blocks. A clean retest against the same endpoint installed the fallback and reached its current `DM-Agear` map download, server welcome, login, and possession without a renderer abort; the old `DM-Unreality][` package was not selected, so that specific compatibility issue remains open. Evidence is in `docs/evidence/engine-startup/2026-08-23-ios-sim-stub/bc1-remote-engine.stdout` and `bc1-remote-system.log`.

A refreshed direct connection to `unreal://217.154.81.36:7777` reached the endpoint's current `DM-Liandri` map. The original engine received `DLMGR ... COMPRESSION=1`, completed the server welcome, loaded the downloaded map, and possessed the player with the BC1 fallback installed. This is current compressed-map interoperability evidence, not proof of the unavailable historical `DM-Unreality][` package. Evidence: `docs/evidence/engine-startup/2026-08-23-ios-sim-stub/network-refresh-engine.stdout`, `network-refresh-engine.log`, and `network-refresh-pass.png`.

The host also starts `NWPathMonitor` and declares local-network usage text so path readiness and permission behavior can be recorded on Apple hardware. Simulator menu accessibility confirms the direct-connect field and button are present; physical-device network permission behavior remains untested.

The original v469e `Multiplayer → Find Internet Games` browser opens with complete localized tab labels and resolves/renders the live OldUnreal News page. The Retina-scaled diagnostic exposed UWindow's additional `MouseScale=0.6`; the Apple profile now uses `MouseScale=1.0`, delivers logical SDL points to the focused window, and sends motion before button edges. A bounded Simulator rerun selected the original `UT Servers` tab, visibly listed 775 servers, and captured the stock GameSpy/HTTP master and individual-server ping paths. The Simulator slice passes; physical finger input, device networking, and joining from a selected row remain open. Evidence: `docs/evidence/network/2026-08-24-original-server-browser/RESULT.md`.

An explicit clean simulator request for `unreal://ut99.weba.ru:7777/DM-Unreality][` was also exercised. The request reached the endpoint and the native engine rendered a live match, but the server first rotated through `DM-Aim` and did not deliver the requested historical `DM-Unreality][` package. The capture shows the server's original MapVote/Welcome UI over the live scene with the GoldenPad touch rail still composited. This is evidence that the request path and renderer remain live, not evidence that the historical map is available from the current server. Evidence: `docs/evidence/engine-startup/2026-08-23-ios-sim-stub/dm-unreality-request-engine.stdout`, `dm-unreality-request-engine.log`, and `dm-unreality-request-pass.png`.

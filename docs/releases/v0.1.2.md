# UTP 0.1.2

An interrupted rollback from UTP 0.1.0 can leave a restored folder whose backup has already been consumed. Recovery now preserves that folder and the remaining recovery files instead of deleting it. New imports record which items existed before replacement, so recovery can distinguish an originally absent item from a missing backup.

If **Repair game data** appears, use **Get Game Data** or **Import Files** to install a verified replacement. A failed repair keeps the previous recovery state and remains retryable. If a content-only import lacks the required runtime support, UTP stays in setup and directs you to **Get Game Data**. Normal play, Safe Mode and direct launch all require ready data.

Rebuild with PadMint and install over the existing app using the same signing identity. Do not uninstall first. Earlier recovery files are retained after a successful repair; files already lost before this update cannot be reconstructed.

## Validation

- The legacy consumed-backup fixture fails at runtime against the actual 0.1.1 transaction implementation.
- Native regressions cover the legacy upgrade, failed replacement preparation, failed repair and retry, interrupted cleanup, successful repair, incomplete recorded backups, complete older journals and originally absent items.
- App metadata is 0.1.2/build 5. Package and source checks do not establish new physical-device, gameplay or Files-provider acceptance.

Only `UTP-v0.1.2-padmint.json` and `SHA256SUMS` are published. PadMint builds the app locally; no app or game data is included.
